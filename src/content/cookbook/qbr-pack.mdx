title: Build the QBR deck before the agenda
description: Assemble the QBR deck from usage, tickets, and account history, with every claim tied to real data.
publishedAt: 2026-08-19
icon: ri-slideshow-3-line
category: Customer Engineering
collection: Customer health
featured: false
order: 23
difficulty: intermediate
skills:
  - name: QBR narrative structure
    description: Wins, usage story, risks, and the ask, in that order.
  - name: Value-story grounding
    description: Tie every claimed win to a real usage or ticket data point.
  - name: Presentation builder
    description: Turn the narrative into a formatted deck with the pptx skill.
goal: assemble the QBR deck from usage, tickets, and account history and ground every claim in real data
integrations: [posthog, zendesk, salesforce, slack]
whatItDoes:
  - Pulls usage trend, ticket history, and contract facts since the last QBR
  - Drafts the narrative, top wins, open risks, and the ask
  - Drops any win not backed by a real usage or ticket data point
  - Builds the deck and a text narrative, ready for the CSM to review
howToUse:
  - Connect PostHog, your support tool, Salesforce, and Slack
  - Set the trigger to the QBR date on the calendar, or run it manually
  - Paste the prompt and set what counts as a "win" for your policy
  - Review the deck and narrative before the customer meeting
workflow:
  - kind: trigger
    title: QBR scheduled on the calendar
    body: Or a manual kickoff two weeks out.
  - kind: prompt
    title: Pull the account story
    body: Usage trend, ticket history, and value delivered since the last QBR.
  - kind: prompt
    title: Draft the narrative
    body: Wins, risks, and the ask for next quarter.
  - kind: shell
    title: Build the deck
    body: Turn the narrative into slides with the presentation skill.
  - kind: result
    title: Deliver for review
    body: Deck saved to drive, summary posted to Slack.
prompt: |
  Build the QBR pack for {{account}}, quarter {{quarter}}.

  1. Pull {{account}}'s usage trend from PostHog, ticket history from
     {{support_tool}}, and deal/contract facts from {{crm}} since the last
     QBR ({{last_qbr_date}}).
  2. Draft the narrative: top 3 wins (with the usage or ticket data behind
     each), any open risk, and the ask for next quarter.
  3. Validation: check every claimed win and risk against its source data
     point. Drop any line that isn't backed by a real number or a real
     ticket, don't soften it, remove it.
  4. Build the deck from the narrative using the presentation skill: title,
     wins, usage story, risks, next-quarter ask.
  5. Save the deck to `documents/qbr/{{account}}-{{quarter}}.pptx` and a text
     version of the narrative to `reports/qbr/{{account}}-{{quarter}}.md`.
  6. Post a summary to {{delivery_channel}}: deck link, top win, top risk,
     for the CSM to review before the customer meeting.

  Do not send the deck to the customer directly, it is a draft for the CSM
  to review, adjust tone on, and present themselves.
